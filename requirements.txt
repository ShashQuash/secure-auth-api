# bcrypt is held at 4.0.1 on purpose. passlib 1.7.4 runs an internal self-test
# on first use that hashes a password longer than 72 bytes. bcrypt 4.1 and
# later refuse that instead of silently truncating, so passlib raises
# "ValueError: password cannot be longer than 72 bytes" and every hash call
# fails. Verified against bcrypt 5.0.0. The fix is to drop passlib and call
# the bcrypt library directly, not to bump this number.
bcrypt==4.0.1
